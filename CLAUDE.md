# nvwrist.github.io

GitHub Pages сайт. Корень — `index.html` (витрина Parfum Store, не трогать без запроса).
`viewer/` — **PS1 3D Viewer**: three.js-просмотрщик моделей в стиле PlayStation 1 с одним персонажем «Странник» на тёмно-фэнтезийном балконе.
Live: https://nvwrist.github.io/viewer/ (пользователь пишет по-русски, UI и ответы — на русском).

## Как пересобрать персонажей
```bash
pip install bpy numpy pillow             # bpy = Blender как python-модуль (~370 МБ), ставится через pip в облачной сессии
python3 viewer/tools/make_human.py       # → viewer/models/human.glb (качает исходник с OpenGameArt, ~6 с)
cd viewer && python3 -m http.server 8123 # открыть http://localhost:8123/
```
Проверка визуально: Playwright + Chromium (`/opt/pw-browsers/chromium`, флаги `--use-angle=swiftshader --enable-unsafe-swiftshader --no-sandbox`).
`window.__ps1` (в main.js) отдаёт `{S, scene, camera, controls, renderer, setEnv, look, animator, randomize, editor}` для скриптов-скриншотов.
Скриншоты клади в scratchpad, не в репозиторий. Не используй `pkill -f` для остановки http.server — убивает оболочку; запускай сервер в фоне и просто оставь.

## Инструменты и скиллы, которые нашли (для качественных моделей)
- **bpy (pip)** — главный инструмент: полноценный Blender без GUI. Меши, скелет, веса, ключи анимации, экспорт glTF.
- **numpy + Pillow** — процедурная геометрия и рисование текстурного атласа (пиксель-арт, NEAREST).
- **trimesh** (pip) — быстрая проверка/статистика мешей, если понадобится.
- **Playwright + Chromium** — скриншоты вьюера для визуальной проверки (в облаке software-GL работает).
- Реестр MCP (проверено ещё раз 2026-10): готовых Blender/3D-генерирующих коннекторов нет; blender-mcp (open source) работает только с Blender + Claude Desktop на компьютере пользователя, в облачной сессии он не нужен — bpy доступен напрямую. Есть «Three.js 3D Viewer» (демо-рендер, не нужен) и «Trimble SketchUp» (не подключён, не для персонажей). Скиллов по 3D-моделированию в каталоге нет — поэтому добавлен проектный скилл `.claude/skills/ps1-character/`.
- Если нужен «художественный» уровень (скульпт, ретопология) — это ручной Blender/Nomad на стороне пользователя; результат можно загрузить во вьюер как .glb (drag & drop).

## Предпочтения пользователя
- Хочет «как на PS1-скринах из инсты» (тёмное фэнтези, грязные пиксельные текстуры, туман), **не киберпанк**, обычный человек.
- Готовые модели из интернета — ок. Брать только **CC0** (Quaternius: quaternius.com / opengameart.org, Kenney). У Quaternius архивы на OpenGameArt качаются curl'ом напрямую; на quaternius.com ссылки ведут на Google Drive.
- Плоские «цветные полосы» на текстуре выглядят дёшево — всегда запекать шум/AO в маленькую текстуру с NEAREST.
- Нужен **только один персонаж** (Странник) + сцена-балкон. Киберпанк-сцены и Neon Runner v1/v2 удалены по просьбе пользователя (есть в истории git). Персонаж грузится в `showHero()` (main.js); имена клипов переводятся через `CLIP_RU`; источник модели — в `models/CREDITS.md`.
- Pages кэширует файлы на 10 минут: `index.html` грузит `main.js?t=<now>`, glb тоже с `?t=` — не ломать это.

## Персонажи
Селектор «Персонаж» (вкладка «Персонаж»): **Странник** (свой редактор, look.js), **Мужчина** / **Женщина** (Quaternius Universal + наряды, 86 анимаций UAL1+2), **Героини** (Ultimate Modular Women, 24 анимации). Выбор и внешность каждого типа хранятся отдельно (`ps1.hero`, `ps1.look.<type>`), свои анимации — по скелету (`ps1.anims.v1.<rig>`: '' Странник, 'ue' Universal, 'women').
- **Почему Universal без Blender:** Blender-импорт glTF меняет ориентацию костей, и анимации UAL перестают совпадать с моделью. gltf-transform сохраняет узлы как есть.
- Части нарядов/причёски — отдельные glb со своим скелетом; в браузере `adopt()` перепривязывает их к костям базового тела по именам (`mesh.bind(new Skeleton(...), mesh.bindMatrix)`).
- Цвет кожи/волос/оттенок одежды — `material.color` (кожа и волосы в текстурах серые/обесцвеченные). Меняя цвет/карту, обновляй и PS1-копию `m.userData.psMat` (см. `setColor`/`setMap`).
- Аниматор берёт кости из скелета автоматически и подписывает по-русски (`boneLabel`), понимает Mixamo/UE/Quaternius-имена.
- Кэш паков: `/tmp/quaternius` (itch) и `/tmp/quaternius/women` (gdown с Google Drive). В git — только готовые `models/q/*`.
- Платные Source/Pro-версии паков (остальные 8 нарядов Fantasy, доп. анимации Pro) НЕ скачиваются — только бесплатные Standard.

## Внешние редакторы (готовые решения поверх вьюера)
Пользователь просил: если есть готовое решение — использовать его. Поэтому в Мастерской есть кнопки:
- **three.js Editor ↗** — вся модель (со скелетом, анимациями, текстурами) уходит в официальный редактор three.js; там кнопка «↩ Вернуть в PS1 Viewer» экспортирует GLB обратно → вьюер сохраняет его в IndexedDB (`ps1-viewer/models`) и показывает в списке «Персонаж» как «✎ <имя> (правка)».
- **SculptGL ↗** — выбранная деталь уходит как OBJ (сваренные вершины, мировые координаты текущей позы) → лепишь → «↩ Вернуть» отдаёт координаты вершин в том же порядке → Мастерская переносит их на исходную деталь через скиннинг-матрицы (скелет/UV/текстура сохраняются) и сохраняет как обычные правки. Нельзя менять число вершин (Multiresolution/Dynamic topology).
- Обмен — через `window.opener.__ps1Bridge = { kind, data: Promise, receive(msg) }` (та же вкладка-источник, тот же домен). Окно открывается СИНХРОННО в обработчике клика (иначе iOS заблокирует), данные приходят позже через Promise.
- Грабли: (1) данные из другой вкладки — «чужие» ArrayBuffer (`instanceof` не срабатывает) → копировать `new Uint8Array(buf).slice().buffer`; (2) служебные `userData` (orig, psMat, ps1src) и оверлеи Мастерской (`userData.edHelper`) не должны попадать в GLB — экспорт только через `exportClean()`, загрузка — через `sanitize()`; (3) SculptGL не центрирует OBJ в этом режиме — мост вызывает `normalizeAndCenterMeshes` (меняет только матрицу, вершины не трогает).
- Для серьёзной работы на телефоне пользователю можно советовать Nomad Sculpt (iOS, импорт/экспорт glTF), на ПК — Blender или web.blockbench.net; результат грузится во вьюер кнопкой «Загрузить».

## Мастерская (js/editor.js) — как устроено
- Вход: 🛠 в шапке или кнопка во вкладке «Персонаж». На время правки анимация на паузе, PS1-эффект выключен (кнопка «PS1» — превью), поза «Т-поза» (покой, `current.rest`) или «Кадр».
- Правки идут в ЛЮБОЙ позе: сдвиг в мире переводится в координаты меша обратной матрицей скиннинга вершины (`invLinear`: Σw·Bone·BoneInv, с bindMatrix). Не заменяй это на прямую запись мировых координат.
- Вершины «свариваются» по позиции (`prepare` → `groups/members`), иначе правка рвёт швы UV. Квантованные атрибуты (KHR_mesh_quantization у Quaternius) переводятся во Float32 (`floatify`) — с заменой во всех мешах, где атрибут общий (зоны тела Universal делят один атрибут; нормали пересчитываются на геометрии с полным индексом).
- У `BufferAttribute` в three r170 нет `userData` → исходные позиции в `WeakMap ORIG`.
- Покраска — отдельный слой-канвас поверх исходной текстуры (`layers`), ластик стирает слой. После каждого `look.apply` main вызывает `editor.afterLook(root, ключ)` — он заново накладывает слои/правки (look.js Странника перерисовывает текстуру).
- Ключ правок: тип персонажа (`strannik`, `man`, `woman`, `women`) или `file:<имя>` для загруженных файлов. Сохраняются: смещения вершин (дельты), удалённые грани, скрытые детали, цвета материалов, слои покраски (PNG dataURL).
- Режим «Снаряжение» (5): клик — предмет, повторный клик по своему предмету — деталь; гизмо двигает контейнер/гнездо/деталь (undo через op `{type:'fn'}`), числа в см/°/%, ▶ Анимация — проиграть, не выходя (main проверяет `editor.playing`). Поза при входе — «Кадр».
- Материалы: панель «Материал» у любой детали — пресеты matlib (сохраняются в `ps1.edits.<ключ>.mats` по имени материала, «Исходный вид» возвращает карту из `ORIGMAT`).
- Горячие клавиши: 1–5 режимы, Tab объект/правка, G/R/S, A / Alt+A, Ctrl+I, L, O, Alt+Z, X/Delete, H / Alt+H, F, [ ], Ctrl+Z / Ctrl+Shift+Z, Esc. Камера в режимах правки — правая кнопка, 2 пальца или 🎥.

## Снаряжение (js/equip.js) — как устроено
- Пользователь просил: детали (волосы, шапки, оружие) должны **редактироваться**, хват меча — правильный, система готова для своих персонажей/материалов/оружия/одежды. Поэтому всё навесное — предметы в гнёздах, а не меши, прибитые к костям.
- Гнездо = Object3D на кости, рассчитывается в позе покоя: оси тела (up = голова−таз, left = плечи), размеры головы — по видимым вершинам головы **без волос/шапок** (материалы /hair|hat|helmet|hood…/) и без скрытых нарядов. `hu` = высота головы, `fit` = ширина/глубина головы (подгонка причёсок).
- Кисть: Y — от мизинца к указательному (ось кулака, через неё идёт рукоять), Z — к пальцам, X — ладонь (правая) / тыльная сторона (левая); центр — у костяшек, чуть к ладони. Если первая кость пальца у запястья (у «Героинь» Index1 = пястная) — `knuckle()` берёт следующую. Левая и правая — зеркальны (S·M·S, S = flipX).
- Предмет = контейнер (правки пользователя, matrix) → `unit` (перевод единиц: 'm' метры, 'hu' единицы головы, 'world') → содержимое. Стандарт предмета: начало = хват/центр, +Y к острию, +Z вперёд (лезвие, лицо щита).
- Посадка по умолчанию: щит в руке — лицом наружу; у вертикальных (`tilt` в BUILTINS: факел, посох, фонарь) — наклон к «вверх» при опущенной руке.
- Встроенные предметы внешности Странника: id `look:<предмет>` (правки положения хранятся по id, переживают смену цвета). У модульных персонажей ничего встроенного нет — всё из каталога.
- Свои предметы (`u:<id>`): glb в IndexedDB `items`; их форма/детали/материалы сохраняются **в сам предмет** (`markDirty` → `saveUserItem`), поэтому Мастерская не пишет для мешей с `userData.libItem` вершинные дельты в правки персонажа (иначе двойное применение).
- «Сделать одеждой»: перенос весов с ближайшей вершины тела + точная обратная матрица скиннинга в позе покоя (`withRest`), скиннинговые копии `userData.clothingOf`, статичный оригинал скрыт (для экспорта/перепривязки). Правка формы одежды — на копии, при сохранении переносится в оригинал (`syncStaticFromBound`).
- Грабли: (1) `Object3D.clone()` копирует userData через JSON — `userData.orig` после клона уже не материал; (2) у обычного Mesh нельзя ставить `boundingSphere = null` (рендер вызовет несуществующий `computeBoundingSphere`) — только у SkinnedMesh; (3) экспорт предметов — Lambert → Standard (glTF), RUNTIME-ключи вычищаются; (4) у `<select>` событие `input` и `change` — обрабатывать один раз.

## Редактор персонажа и аниматор — как устроено
- Панель: вкладки «Персонаж» (редактор + 🎲 Рандом), «Анимация» (список клипов + аниматор), «Вид» (PS1/сцена/загрузка). 🎲 есть и в шапке.
- Текстура = `цвет_региона(cfg, узор по pos) × shade`. Новый узор/одежда — правка `paint()` в look.js (регионы: 1 кожа, 2 глаза, 3 волосы, 4 рубаха, 5 штаны, 6 обувь; координаты объекта: Y вверх, вперёд +X, лево −Z, T-поза).
- Аксессуары (шапки, причёски, плащи, предметы) — встроенные предметы `items.js` в «единицах головы» (X влево, Y вверх, Z вперёд), look.js только выбирает их и отдаёт в `equip.setBuiltins()`; крепление/хват — гнёзда equip.js (см. «Снаряжение»).
- Меши встроенных предметов помечены `userData.noConvert` (уже PS1-материалы) — `convertMaterials` их не трогает.
- Пропорции (рост/телосложение/голова) применяются каждый кадр после `mixer.update` в `look.update()`.
- Новое поле редактора: добавить в `SCHEMA` + обработать в `paint()` (текстура) или `rebuildAccessories()` + `BUILTINS` (предмет) + учесть в `randomLook()`.
- Состояние: внешность — localStorage `ps1.look.v1`, анимации — `ps1.anims.v1`, снаряжение — `ps1.equip.<тип>`. Экспорт .glb включает предметы (гнёзда — обычные узлы), текстуру и все клипы.
- Грабли запекания карт: (1) ставить `rig.data.pose_position='REST'`, иначе Object-координаты берутся из кадра анимации; (2) id регионов кодировать углами RGB-куба и `cycles.filter_width≈0` — иначе на краях смешение id даёт ложный регион.

## Конвенции и грабли
- Blender: Z вверх, персонаж смотрит в **−Y**, левая сторона = **+X**; glTF-экспорт конвертирует в Y-up/+Z сам.
- Вершинные цвета экспортируются **только** с `export_vertex_color='ACTIVE'`; цвета в скрипте задаются sRGB-hex и переводятся в linear (`lin()`).
- Скелет/анимации берутся из исходника Quaternius как есть (Mixamo-кости: Hips, Spine…, LeftArm…). Новые анимации — добавлять action'ы в Blender в `make_human.py` до экспорта.
